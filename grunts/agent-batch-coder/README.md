# 🛑 Agent Batch Coder

Handing a large coding task to an AI agent and watching it eat its own context window is an inefficient use of both. This bundle is a portable, agent-agnostic "Skill-in-a-Box": the agent breaks the work into small, verifiable tasks and hands each one to Aider in sequence. The agent never types the code itself. It supervises, which is how sensible people operate.

## ⚙️ How the Machinery Works

1. The agent prepares an isolated scratch workspace (`$TASK_DIR`) and writes a `validate.sh` hook into it containing the project's actual build/test command.
2. The agent breaks the feature into strictly sequential, atomic task files (`01_init.md`, `02_database.md`, ...), each naming the target file paths in backticks.
3. `run_tasks.sh` processes the queue one task at a time: it feeds each task to Aider with the validation hook wired up as `--test-cmd --auto-test`, re-runs the hook as a final seal, commits the verified work, tags a checkpoint, and archives the task file into `$TASK_DIR/done/`.
4. On failure the runner stops, announces an alert, and prints recovery instructions (`git reset --hard last_good_checkpoint`). The agent investigates natively, fixes the code with its own tools, and re-runs the script to resume where it left off. That part is not automatable, and I have said this to no one.

## 📜 The Bureaucracy (Installation)

Clone this repository anywhere on your machine, then symlink it into your Hermes skills directory. Do not track the bundle itself in the target project's history unless you enjoy explaining yourself to coworkers.

```bash
git clone https://github.com/yourusername/agent-batch-coder.git ~/tools/agent-batch-coder
ln -s ~/tools/agent-batch-coder ~/.config/hermes/skills/batch-coder
```

## 📋 Standing Orders (Project Requirements)

- The target project must be a **git repository** — the runner checkpoints every task with commits and tags, and it has no patience for unversioned code.
- **Aider** must be installed, configured, and authenticated on the machine. If it is not, the pipeline fails, which is the default state of all things.
- No per-project setup is required: the agent determines the project's correct build/test command (e.g., `go build ./...`, `npm run check`, `cargo check`) and writes it into `$TASK_DIR/validate.sh` itself. The runner picks the hook up automatically and passes it to Aider; if no hook exists, Aider simply runs without auto-testing, which I will not be praising.

## 🚧 The Perimeter (Isolation)

Your project directory remains completely untouched by the management layer. Every artifact generated by the agent — the task queue, the validation script, and the temporary prompts — lives entirely in scratch space, while the Aider worker applies precise edits directly to your codebase. Nothing leaks into the repository that was not built there.
